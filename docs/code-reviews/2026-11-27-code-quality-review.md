## Summary

### What is well built

- **The layering is real.** `src/main.ts` imports `src/ui/` and `src/lib/`, `src/ui/` imports `src/lib/`, and there is no import cycle; the one edge pointing the other way is a type import (ARC-3). Concerns shared with the sibling apps live in the `@brain-bbqs/*` packages, so `src/lib/etag.ts` (9 lines), `errors.ts` (8), `oauth.ts` (18) and `settings.ts` (32) are thin adapters, and every file under `configs/` is one call to a shared factory.
- **The tests test what ships.** 346 unit tests and 67 Playwright tests pass. Unit coverage is 99.82% of statements and 99.17% of branches, with a ratchet just below (`configs/vitest.config.ts:15-20`). The `main.*` suites boot the real `src/main.ts` against the real `index.html` (`tests/unit/helpers/mainHarness.ts:7`). Each of the seven uncovered guards was traced and is unreachable, as `configs/vitest.config.ts:13` says.
- **Late asynchronous results are handled on purpose.** Sequence counters drop stale responses wherever one could land late (`src/main.ts:715-735`, `:1112-1135`, `:1201-1226`). The checksum cache chains operations per key (`src/lib/checksum-cache.ts:126-128`, `:165-176`), and a full cache hit is never trusted without re-hashing one part (`src/lib/etag-worker.ts:160-167`).
- **Comments say why, with sources.** The 409 dedup path (`src/lib/upload-pipeline.ts:28-36` and "Expected console noise" in `docs/README.md`) and the hash pool's design (`src/lib/etag-worker.ts:65-80`) are examples.
- **The security notes match the code.** `SECURITY.md:29-30` says the two `innerHTML` uses are static templates. They are the only two (`src/ui/fileRow.ts:26`, `src/ui/fileTree.ts:54`), and names go in through `textContent` (`fileRow.ts:34`, `fileTree.ts:65`). `chromatic-publish.yml` keeps the project tokens away from the built commit.
- **Closed sets are typed where it matters most.** `RemoteBannerState` (`src/main.ts:1017-1021`), the worker protocol with `satisfies` (`src/lib/etag-worker.ts:4-11`, `:121`, `:140`), `Record<UploadOutcome, number>` (`src/main.ts:287`).
- **No dead styles.** All 117 rules of `src/style.css` applied when the built page was driven through its states with CSS coverage on.
- **CI is current.** Every action is on its latest major, the pre-commit pins are current or one minor behind, and Dependabot (actions) and pre-commit.ci keep them so.

### Themes

1. **One module holds the page.** `src/main.ts` is 1,616 lines, 43% of the TypeScript under `src/`, with 64 functions and 48 module-level bindings. Nothing in it can be imported without booting the page, so Storybook restates its view logic and has drifted (ARC-1), small bodies are repeated inside it (DUP-2, DUP-3, DUP-4, DUP-5), and the test hooks are woven through it (ARC-5). By ESLint's measure the most complex functions are `uploadFile` at 15 (the project's cap, with 7 parameters), then `renderPhaseBar`, `applyRowAppearance` and `listRemoteFiles` at 12; the longest are three state-holding closures (`openChecksumCache` 176 lines, `createHashPool` 167, `createSelectionModel` 136) and `startUpload` (99).
2. **Facts stated in several places.** The destination prefix (ARC-2), the outcome set (ARC-3), what a cancellation looks like (ARC-4), the digest length (ARC-6). In each case one definition exists already and the other places do not use it.
3. **Helpers the shared packages already export, written out again.** `nextPagePath` (DUP-1), `computeDandiEtag` (CON-1), `errorMessage` (CL-5).
4. **Leftovers of earlier designs.** Hashing moved from drop time to the Upload click and the slider changed meaning; names, comments and a few functions still describe the old behavior (DC-1, CL-1, CL-3, CL-4, NV-7, NV-10).

### Architecture

#### ARC-1: The page controller is one module, and stories restate it <a id="arc-1"></a>

- **Location**: `src/main.ts:1-1616`. Restated in `stories/selectionCard.ts:53-81`, `:83-106`, `:112-132`, `:142-149`, `:157-179`, `:192-240`; `stories/injections/MockUpload.stories.ts:13-35`, `:37-78`; `stories/UploadCard.stories.ts:51`.
- **Issue**: nothing can be imported from `main.ts` without booting the page (element lookups at `:64`, top-level `await` at `:1487`), so Storybook cannot render the code that ships. `stories/selectionCard.ts:3-5` says so: its glue is duplicated because "main.ts's wiring is bound to the page-level element registry and can't be imported piecemeal". The copies have drifted (each OBSERVED by diff):
  - `applyRowAppearance` (story `:53-81`, `src/main.ts:896-931`): the story has no `consumed` branch (`main.ts:899-903`) and never sets the checkbox tooltip (`:908`, `:914`).
  - Remote banner (story `:192-240`, `src/main.ts:1017-1067`): the story's state type has no `browse` kind (`main.ts:1020`), so two of the page's banner texts are never drawn in Storybook.
  - Ignore box: the story's Enter handler omits `preventDefault()` (story `:151-153`, `main.ts:1558-1563`).
  - Tree: the story joins the destination path without `sanitizePath` (story `:165`, `src/ui/processFile.ts:32-33`) and skips the collapse of fully uploaded folders (`main.ts:1092-1099`). `MockUpload.stories.ts:13-35` is a second tree renderer, without checkboxes.
  - `stories/DatasetCard.stories.ts:23-24` shows options as "Title (id)" where the page renders "(id) Title" (`main.ts:788`); `stories/UploadCard.stories.ts:52` disables the Upload button where the page hides it (`main.ts:889`).

  The Chromatic Storybook snapshots therefore review the copies. The same structure is why pure logic such as `sampleRate` (`:323-338`) and `etaText` (`:436-441`) can only be tested through a booted page with fake timers.

- **Proposed change**: extract in steps. Each step moves code verbatim and turns closure variables into arguments, as `initDropzone(els, onFolder)` already does (`src/ui/dropzone.ts:144`).
  1. `src/ui/remoteBanner.ts`: `RemoteBannerState` and `renderRemoteBanner(els, state)`. They touch five elements and no module state. The story builds the skeleton and calls it.
  2. `src/ui/selectionView.ts`: `applyRowAppearance(row, file, hasRemote)`, the folder and summary half of `refreshSelectionUI` (`:936-955`), and `renderIgnoreChips(container, patterns, onRemove)`. `stories/selectionCard.ts` keeps only its markup.
  3. `src/lib/progress-rate.ts`: `RateTracker`, `sampleRate` (taking `now` as an argument) and `etaText`, with direct unit tests.
  4. Later and optional: the dataset picker (`:662-871`) and the progress summary (`:377-481`) as modules of their own.

  An extracted module must not look up elements or read `location.search` at module scope: tests set both before `main.ts` is imported.

- **Confidence it's safe**: **Medium**. No test imports anything from `src/main.ts` except the harness's dynamic import. 26 `main.*` suites and 67 integration tests assert on the DOM the moved code writes. Top-level `await` and microtask depth are not pinned tightly (the mock-upload suites have about 17 turns of headroom). What lowers the rating: the stories have no type check (NV-2) and no unit test, so their half is guarded only by the Storybook build and Chromatic, where the drift listed above will appear as diffs to accept. The extraction itself was not run in this review.
- **Verification**: `npm run typecheck && npm run lint && npm test && npm run test:integration && npm run build-storybook`, then review the Chromatic diffs of "Components/Upload card", "Components/Selection tree" and "Components/Remote contents banner".

#### ARC-2: The destination prefix `sourcedata/raw` is spelled six times in `src/` <a id="arc-2"></a>

- **Location**: `src/lib/remote-listing.ts:5` (`REMOTE_PREFIX`), `src/ui/processFile.ts:32`, `src/lib/transfer-report.ts:18`, `src/main.ts:1165` (twice), `src/main.ts:1208`. The hidden folder `.transfer`: `src/lib/remote-listing.ts:49`, `src/lib/transfer-report.ts:18`. `src/main.ts:876` derives the form without the slash by regular expression.
- **Issue**: where uploads land is the fact that the "already on EMBER" diff, the browse, the transfer report and the row paths must agree on, and each states it on its own: `["sourcedata", "raw", ...]`, `"sourcedata/raw/"` (twice), `"sourcedata/raw"`, and a template literal. Changing the destination takes six edits in four files, and nothing fails if one is missed: `tests/unit/remote-listing.test.ts:33` builds its expectation from `REMOTE_PREFIX` itself.
- **Proposed change**: in `src/lib/remote-listing.ts` define `export const REMOTE_DIR = "sourcedata/raw";`, derive `REMOTE_PREFIX` as `` `${REMOTE_DIR}/` ``, and add `export const TRANSFER_REPORT_DIR = ".transfer";`. Then: `processFile.ts:32` starts its prefix from the constant; `main.ts:1165` uses `REMOTE_PREFIX` and its length; `main.ts:1208` and `:876` use `REMOTE_DIR`; `transfer-report.ts:18` uses `` `${REMOTE_PREFIX}${TRANSFER_REPORT_DIR}/…` ``; `HIDDEN_BROWSE_DIRS` lists `TRANSFER_REPORT_DIR`. Two traps: `main.ts:1208` needs the form without the slash (a doubled slash would go unnoticed, since `:1166` absorbs it), and the report path must stay out of `sanitizePath`, which strips the leading dot (`transfer-report.ts:10-13`).
- **Confidence it's safe**: **High**. The derived strings equal today's for 76 combinations of folder and file name through `sanitizePath` (the form tried was `sanitizePath(REMOTE_PREFIX + relativePath, …)`). With the change applied in a throwaway copy, typecheck and lint are clean and 346 tests pass.
- **Verification**: `npm run typecheck && npm test && npm run test:integration`. Tests that pin the strings: `tests/unit/processFile.test.ts:63`, `:69`; `tests/unit/transfer-report.test.ts:54-56`; `tests/integration/folder-drop.spec.ts:25`.

#### ARC-3: The upload outcome set lives in the UI layer and is restated in six more places <a id="arc-3"></a>

- **Location**: `src/ui/processFile.ts:14` (the union). `src/lib/transfer-report.ts:2` (a `src/lib/` module importing the type from `src/ui/`) and `:30`. `src/main.ts:287` (initial counts), `:444` (sum), `:474-480` (footer text), `:1440-1444` (reset). `src/schemas/transfer-report.v1.schema.json:97` (enum). `tests/unit/transfer-report.schema.test.ts:73` (a hand-written list).
- **Issue**: adding one outcome takes edits in seven places, and one is checked. OBSERVED by experiment: with a sixth value added to the union and to `:287` (which `tsc` does demand, TS2741), `tsc` exits 0 and all 346 tests pass, while the sum, the reset, the footer, the schema enum and the schema test's own list all lack the value. The test named "enumerates every real status value" compares the schema with a list written in the test, and nothing checks that list's type annotation (NV-2). Separately, `transfer-report.ts:2` is the only import in `src/lib/` that points at `src/ui/`.
- **Proposed change**: a new `src/lib/upload-outcome.ts` with `export const UPLOAD_OUTCOMES = ["blocked", "cancelled", "error", "replaced", "done"] as const;` and `export type UploadOutcome = (typeof UPLOAD_OUTCOMES)[number];`. `processFile.ts` and `transfer-report.ts` import the type from there (`processFile.ts` re-exports it so other importers keep working). `main.ts` builds `counts` from the list, sums with `UPLOAD_OUTCOMES.reduce(...)` and resets with a loop. The schema test compares the enum with `["pending", ...UPLOAD_OUTCOMES]`, and the schema description at `:98` points at the new file. Afterwards a new outcome is two edits (the list and the schema enum), and the test fails if they differ. Keep the list out of any module a test automocks: placed in `etag-worker.ts`, three tests fail, because automocking empties arrays.
- **Confidence it's safe**: **High**. Tried in a throwaway copy (the list in a new `src/lib/` module; counts built, summed and reset from it): typecheck and lint clean, 346 tests pass, coverage floors hold. The key order of `counts` changes; nothing iterates it.
- **Verification**: `npm run typecheck && npm test`. No test pins the reset or most of the sum (dropping any line of `:1440-1444` still passes), so read that part of the diff.

#### ARC-4: A cancelled operation is built three ways and recognized two ways <a id="arc-4"></a>

- **Location**: built as `new DOMException("Aborted", "AbortError")` at `src/main.ts:195`, `src/lib/mockUpload.ts:95`, `:102`, `src/lib/remote-listing.ts:29`; as `new DOMException("Upload cancelled.", "AbortError")` at `src/lib/etag-worker.ts:233`, `:252`; as `new Error("Upload cancelled.")` at `src/lib/s3-upload.ts:32`, `:49`. Recognized by `e instanceof DOMException && e.name === "AbortError"` at `src/main.ts:148`, `:267`, `src/ui/processFile.ts:102`, and by `/cancelled/i.test(message)` at `src/lib/s3-upload.ts:55`.

- **Confidence it's safe**: **High**. Traced: no cancel message reaches the page (the cancel branches only set the "Cancelled" badge), and no test asserts "Aborted". With `isAbortError` in `errors.ts`, 346 tests pass.
- **Verification**: `npm run typecheck && npm test && npm run test:integration`. `tests/unit/etag-worker.test.ts:168` and `tests/unit/s3-upload.test.ts:131-145` pin the two messages that stay.

#### DUP-1: The asset-listing pagination loop is written twice, and its page step is in the shared package <a id="dup-1"></a>

- **Location**: `src/lib/remote-listing.ts:25-41`, `src/lib/upload-pipeline.ts:116-129`.
